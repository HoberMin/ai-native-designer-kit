# 새 스킬 · 서브에이전트 만들기

자세한 기준과 예시는 `docs/1-skill-guide.md`, `docs/2-subagent-guide.md`에 있어요. 만들기 전에 해당 문서를 읽어요.

## 순서

1. **중복 확인** — `.claude/skills/`, `.claude/agents/`, `CLAUDE.md`의 표를 봐요. 비슷한 게 있으면 **새로 만들지 말고 기존 것을 고치자고** 제안해요.
2. **종류 고르기** — 사용자에게 이유와 함께 하나를 제안해요.
   - 매번 지켜야 하는 짧은 규칙 → `CLAUDE.md`에 한 줄
   - 순서가 있는 반복 작업, 중간에 같이 보며 고침 → **스킬** (대부분 여기)
   - 많이 읽고 오래 걸림, 다른 눈으로 검수, 결과만 보면 됨 → **서브에이전트** (처음엔 읽기 전용)
3. **세 가지 질문** (대화에서 이미 나왔으면 생략)
   - 언제 쓰나요? 실제로 할 말 2~3개
   - 어떤 순서로 하나요? / 어떤 모양으로 보고받고 싶나요?
   - 절대 하면 안 되는 건?
4. **초안 보여주기** — 파일 전체를 보여 주고, 특히 `description`을 한 번 더 확인받아요.
5. **작성**
   - 스킬: `.claude/skills/<영문-이름>/SKILL.md`
   - 서브에이전트: `.claude/agents/<영문-이름>.md`
   - 형식은 가이드 문서의 “해부” 예시를 따라요. 본문은 한 화면 안으로.
6. **등록** — `CLAUDE.md`의 “스킬과 서브에이전트” 표에 한 줄. `docs/skill-backlog.md`에 있던 항목이면 상태를 “완료”로.
7. **써보기** — 사용자에게 시험 문장 두 개를 드려요.
   - 꺼내져야 하는 말 (description에 적은 말)
   - 꺼내지면 안 되는 비슷한 말
   결과가 이상하면 말로 고치게 해요: “3번 단계는 빼줘”, “이럴 때도 쓰게 해줘”.
8. **공유** — 원하면 `ship` 스킬로 커밋.

## 규칙

- 스킬 하나 = 일 하나. 길어지면 둘로 나누자고 제안해요.
- 사용자의 판단 기준(체크리스트)을 최대한 사용자 말 그대로 옮겨요. 내가 기준을 지어내지 않아요.
- 서브에이전트는 사용자가 원하지 않는 한 **파일을 고치지 않는 읽기 전용**으로 만들어요.
